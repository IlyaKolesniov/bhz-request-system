# Техническое задание

## 1. Назначение и область применения

Система предназначена для компании BHZ и заменяет учёт заявок в WhatsApp, Excel и на телефонах сотрудников единым веб-приложением. Она охватывает путь заявки от обращения клиента до выполнения монтажа и обеспечивает монтажника полной информацией до выезда на объект.

Цели: сократить обработку заявки с 20–30 до 5–10 минут, снизить долю заявок с уточняющими звонками с 20–30% до менее 5%, снизить долю случаев нехватки оборудования с 10–20% до менее 5%.

## 2. Роли и права доступа

| Действие | Администратор | Менеджер | Монтажник |
|---|---|---|---|
| Создавать и редактировать заявки | да | да | нет |
| Просматривать все заявки | да | да | нет |
| Просматривать назначенные заявки | да | да | да (только свои) |
| Назначать монтажника | да | да | нет |
| Менять статус | да | да | да (свои заявки: «В работе», «Выполнена») [допущение] |
| Добавлять комментарии и фото | да | да | да (свои заявки) |
| Управлять пользователями | да | нет | нет |

Роль «руководитель» в первой версии совпадает с ролью администратора [допущение].

## 3. Функциональные модули

1. **Аутентификация и пользователи.** Вход, роли, управление учётными записями (FR-13, FR-14).
2. **Заявки.** Создание, редактирование, карточка, статусы, история, комментарии (FR-01, FR-02, FR-07, FR-08, FR-11, FR-15).
3. **Фотографии объекта.** Загрузка и просмотр (FR-03).
4. **Оборудование заявки.** Список позиций с количеством (FR-04).
5. **Назначение и график.** Монтажник, дата и время установки (FR-05, FR-06).
6. **Список и поиск.** Единый список, фильтры, поиск (FR-09, FR-10).
7. **Кабинет монтажника.** Только свои заявки со всеми данными (FR-12).

## 4. Сущности данных и связи

- **User**: id, логин, хэш пароля, ФИО, телефон, роль, активен.
- **Request** (заявка): id, имя клиента, телефон клиента, адрес, тип объекта, количество камер, дата и время установки, статус, id менеджера-автора, id монтажника, дата создания.
- **EquipmentItem**: id, id заявки, наименование, количество.
- **Photo**: id, id заявки, путь к файлу, дата загрузки, id загрузившего пользователя.
- **StatusHistory**: id, id заявки, прежний статус, новый статус, id пользователя, время.
- **Comment**: id, id заявки, id автора, текст, время.

Связи:
- User (менеджер) 1 — N Request; User (монтажник) 1 — N Request.
- Request 1 — N EquipmentItem, Photo, StatusHistory, Comment.
- User 1 — N StatusHistory, Comment, Photo.

Данные клиента (имя, телефон, адрес) хранятся в самой заявке, отдельной сущности «клиент» в первой версии нет [допущение: заказчик не просил историю клиента].

## 6. Технологический стек

| Слой | Выбор | Обоснование |
|---|---|---|
| Бэкенд | Python 3 + Django | В готовом виде есть аутентификация, роли, админ-панель, ORM и защита от типовых уязвимостей, поэтому укладываемся в срок 1–2 месяца и бюджет 500 000 ₸ |
| База данных | PostgreSQL | Надёжная реляционная БД для связанных сущностей (заявка — оборудование — фото), бесплатная |
| Интерфейс | HTML-шаблоны Django + Bootstrap | Адаптивная вёрстка для компьютера и телефона без отдельного мобильного приложения |
| Хранение фото | Файловая система сервера (папка media) | Простота для первой версии, при росте можно перейти на объектное хранилище |
| Развёртывание | Docker, Nginx, HTTPS (Let's Encrypt), VPS | Дешёвый хостинг, воспроизводимая установка, шифрование соединения (NFR-04) |
| Резервные копии | Ежедневный скрипт `pg_dump` + копия папки media | Выполнение NFR-05 |
| Репозиторий | GitHub | Требование задания |

Стек выбран исходя из задач и бюджета, его можно заменить на привычный автору, если требования остаются выполнимыми.

## 7. Ограничения и допущения

**Ограничения (от заказчика):**
- бюджет первой версии около 500 000 ₸;
- срок 1–2 месяца;
- работа через браузер на компьютере и телефоне;
- в первую версию не входят видеозвонки, онлайн-оплата, бухгалтерия, сложная аналитика, мобильное приложение в магазинах приложений, интеграции с другими сервисами.

**Допущения (нужно подтвердить у заказчика):**
- не более 20 одновременных сессий, 10–15 заявок в день (последнее названо заказчиком);
- список статусов и права ролей как в разделе 2;
- до 10 фото на заявку, до 10 МБ каждое;
- интерфейс на русском языке;
- старые заявки из Excel не переносятся;
- хостинг и поддержка на стороне заказчика или автора по договорённости.

## 8. Критерии приёмки первой версии

1. Выполнены требования FR-01…FR-15 и NFR-01…NFR-06 с описанными проверками.
2. Хронометраж: создание полной заявки занимает не более 10 минут (цель 5–10).
3. Монтажник получает все данные заявки до выезда без обязательного звонка менеджеру.
